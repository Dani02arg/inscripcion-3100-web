# Guía detallada de cursos

Base URL local: `http://localhost:8000`
Prefijo API: `/api`

Todas las rutas requieren un JWT:

```http
Authorization: Bearer <token>
Accept: application/json
Content-Type: application/json
```

Los roles permitidos en lectura son `TUTOR`, `ADMINISTRATIVO` y
`ADMINISTRADOR`. Crear, modificar, eliminar, clonar u ocultar cursos requiere
`ADMINISTRATIVO` o `ADMINISTRADOR`.

## Endpoints

| Método | Endpoint | Acceso | Función |
|---|---|---|---|
| GET | `/api/courses` | Los tres roles | Lista cursos paginados. |
| GET | `/api/courses/available?year=2026` | Los tres roles | Cursos activos con cupos disponibles para un año. |
| GET | `/api/courses/{course}` | Los tres roles | Consulta un curso. |
| GET | `/api/courses/{course}/report` | Los tres roles | Reporte del curso y sus inscripciones activas. |
| POST | `/api/courses/create` | Roles altos | Crea un curso. |
| PUT/PATCH | `/api/courses/{course}` | Roles altos | Actualiza campos del curso. |
| DELETE | `/api/courses/{course}` | Roles altos | Elimina lógicamente un curso sin inscripciones activas. |
| POST | `/api/courses/{course}/clone` | Roles altos | Crea un curso a partir de otro. |
| PATCH | `/api/courses/{course}/hide` | Roles altos | Cambia el estado a inactivo. |
| PATCH | `/api/courses/{course}/show` | Roles altos | Cambia el estado a activo. |
| POST | `/api/courses/clone/{oldYear}` | Roles altos | Copia cursos del año indicado al año actual. |

`{course}` es el UUID del curso. Los endpoints de cursos responden JSON; las
colecciones de recursos se devuelven bajo `data`. Las colecciones paginadas
incluyen también `links` y `meta`.

## Formato de curso

```json
{
  "id": "uuid-del-curso",
  "code": "2026-1-1-BAS-INF-M",
  "year": 2026,
  "studyYear": 1,
  "division": "1",
  "cycle": "basic",
  "speciality": "informatics",
  "shift": "morning",
  "maxCapacity": 30,
  "currentCapacity": 10,
  "availablePlaces": 20,
  "status": "active",
  "created_at": "2026-11-02T18:30:00+00:00",
  "updated_at": "2026-11-02T18:30:00+00:00"
}
```

`code` se genera desde los campos académicos. `availablePlaces` es
`maxCapacity - currentCapacity`. Los valores permitidos son:

- `studyYear`: entero del 1 al 6.
- `cycle`: `basic` o `superior`.
- `speciality`: `basic`, `informatics` o `electronics`.
- `shift`: `morning`, `afternoon` o `night`.
- `status`: `active` o `inactive`.

## Consultar cursos

### Listar cursos

```http
GET /api/courses?per_page=15&page=1
```

`per_page` es opcional y por defecto es 15. La respuesta es paginada y ordena
por año de estudio, división y turno.

Ejemplo de estructura:

```json
{
  "data": [
    {
      "id": "uuid-del-curso",
      "code": "2026-1-1-BAS-INF-M",
      "year": 2026,
      "studyYear": 1,
      "division": "1",
      "cycle": "basic",
      "speciality": "informatics",
      "shift": "morning",
      "maxCapacity": 30,
      "currentCapacity": 10,
      "availablePlaces": 20,
      "status": "active",
      "created_at": "2026-11-02T18:30:00+00:00",
      "updated_at": "2026-11-02T18:30:00+00:00"
    }
  ],
  "links": {},
  "meta": {}
}
```

### Listar cursos disponibles

```http
GET /api/courses/available?year=2026
```

`year` es opcional; si se omite, se usa el año actual. No está paginado.
Devuelve solo cursos `active` cuyo `currentCapacity` sea menor que
`maxCapacity`; incluye `availablePlaces` y `pendingRequests`.

```json
{
  "data": [
    {
      "id": "uuid-del-curso",
      "code": "2026-1-1-BAS-INF-M",
      "year": 2026,
      "studyYear": 1,
      "division": "1",
      "cycle": "basic",
      "speciality": "informatics",
      "shift": "morning",
      "maxCapacity": 30,
      "currentCapacity": 10,
      "availablePlaces": 20,
      "pendingRequests": 2,
      "status": "active",
      "created_at": "2026-11-02T18:30:00+00:00",
      "updated_at": "2026-11-02T18:30:00+00:00"
    }
  ]
}
```

### Consultar un curso

```http
GET /api/courses/{course}
```

Responde `200` con un recurso de curso. Responde `404` si el UUID no
corresponde a un curso disponible.

## Administrar cursos

### Crear curso

```http
POST /api/courses/create

{
  "year": 2026,
  "studyYear": 1,
  "division": "1",
  "cycle": "basic",
  "speciality": "informatics",
  "shift": "morning",
  "maxCapacity": 30
}
```

Todos los campos del ejemplo son obligatorios. `year` debe ser el año actual
o futuro; `maxCapacity` debe ser un entero mayor que cero. `status` es
opcional y acepta `active` o `inactive`; si se omite se crea como `active`.
La combinación año, año de estudio, división, ciclo, especialidad y turno
debe ser única.

Responde `201` con el curso creado. El curso empieza con
`currentCapacity: 0`.

### Actualizar curso

```http
PATCH /api/courses/{course}

{
  "maxCapacity": 40,
  "shift": "afternoon"
}
```

También se puede usar `PUT`. Envíe solo los campos que desea modificar:
`year`, `studyYear`, `division`, `cycle`, `speciality`, `shift`,
`maxCapacity` y `status`. Se aplican las mismas restricciones de formato y
valores que al crear. No se pueden enviar `id`, `code` ni `currentCapacity`
como campos modificables.

`maxCapacity` debe ser mayor que cero y no puede quedar por debajo de
`currentCapacity`. La nueva combinación académica debe seguir siendo única.
Responde `200` con el curso actualizado.

### Eliminar curso

```http
DELETE /api/courses/{course}
```

Si `currentCapacity` es mayor que cero, responde `422`:

```json
{
  "error": "No puede eliminar un curso con inscripciones activas."
}
```

Si no tiene inscripciones activas, aplica eliminación lógica y responde `204`
sin cuerpo.

### Clonar curso

```http
POST /api/courses/{course}/clone

{
  "year": 2027,
  "maxCapacity": 40
}
```

Todos los campos son opcionales; los omitidos se copian del curso original,
excepto `status`, que por defecto será `active`. Se admite modificar `year`,
`studyYear`, `division`, `cycle`, `speciality`, `shift`, `maxCapacity` y
`status`.

El curso nuevo empieza con `currentCapacity: 0` y no copia inscripciones. La
combinación académica debe ser única; por ejemplo, clonar sin cambiar año ni
ningún otro campo de esa combinación normalmente produce conflicto de
validación (`422`).

Responde `201` con el curso nuevo.

### Ocultar y mostrar curso

```http
PATCH /api/courses/{course}/hide
PATCH /api/courses/{course}/show
```

`hide` cambia el estado a `inactive`; `show` lo cambia a `active`. El body es
opcional. También acepta `{"status":"active"}` o
`{"status":"inactive"}`. No se puede pasar a inactivo un curso con
inscripciones activas. Si la regla de negocio impide el cambio, la operación
falla; no se debe asumir una respuesta exitosa.

Cuando se completa, responde `200` con el curso actualizado.

### Clonar año académico

```http
POST /api/courses/clone/2025
```

No requiere body. Copia al año calendario actual los cursos del año indicado,
manteniendo sus campos académicos, estado y cupo máximo. Las copias empiezan
con `currentCapacity: 0` y sin inscripciones. Omite las combinaciones que ya
existen en el año destino. Si no existen cursos de origen o todos colisionan,
puede responder `201` con `cloned: 0`.

```json
{
  "message": "Cursos clonados del año 2025 al año 2026",
  "cloned": 2,
  "courses": [
    {
      "id": "uuid-del-curso",
      "code": "2026-1-1-BAS-INF-M",
      "year": 2026,
      "studyYear": 1,
      "division": "1",
      "cycle": "basic",
      "speciality": "informatics",
      "shift": "morning",
      "maxCapacity": 30,
      "currentCapacity": 0,
      "availablePlaces": 30,
      "status": "active"
    }
  ]
}
```

## Reporte del curso

```http
GET /api/courses/{course}/report
```

Devuelve cabecera y alumnos con inscripción activa, ordenados por apellido y
nombre:

```json
{
  "header": {
    "courseDivision": "1º 1",
    "speciality": "informatics",
    "year": 2026,
    "shift": "morning",
    "totalInscriptions": 1
  },
  "list": [
    {
      "orderNumber": 1,
      "lastname": "García",
      "firstname": "María",
      "dni": "12345678",
      "phone": "3871234567",
      "email": "maria.garcia@example.com"
    }
  ]
}
```

La ruta actualmente permite los tres roles, incluido `TUTOR`; el reporte
incluye datos personales de los alumnos. Responde `404` si el curso no existe.

## Errores habituales

| Código | Significado |
|---|---|
| 401 | Falta el JWT o no es válido. |
| 403 | El rol no permite la operación. |
| 404 | Curso inexistente. |
| 422 | Datos inválidos, combinación duplicada o regla de negocio incumplida. |
